# Reconstruction target and remaining work

The target is **mig33 Java ME v4.62 build .000**. Direct messages and public chat rooms remain central, and the requested scope now includes **the full52-template historical page catalog and its local services**. Private group conversations, public rooms and website community **Groups** are separate features with separate membership models.

The current milestone is the **local v4 backend**: all advertised original-client flows have persistent implementations, recovered behavior where evidence exists, and explicit inferred replacements or placeholders elsewhere. SMS, external email, calls and payments remain mocked; external IM stays disconnected while its future scope is undecided. These provider choices are accepted boundaries, not unfinished real integrations.

Expo/React Native and **Settings → Experience → Classic v3** are deferred UI work over the same backend. The v3 option is a presentation/behavior setting in that future app, not a separate backend implementation requirement. The current executable UI is the original Java applet.

Updated **2026-10-28**. **DONE** means implemented for the stated local contract, **PARTIAL** means useful behavior with a material gap, and **MISSING** means absent. Route coverage does not mean historical product parity, exact design recovery, provider integration or production readiness.

## Compatibility boundaries

- **Kick versus ban:** native706 removal and popup5 do not forcibly close the original room tab. Room bans now reject rejoin separately. No unverified forced-close opcode is invented.
- **Block versus mute:**417 carries a username without a room and always emits native mode2. The stock Block & Mute item remains a personal block; room709/710 and Room Info controls are separate moderator actions.
- **Groups:** private conversations, community membership and linked rooms have different authorization. A community role does not automatically grant room moderation, and linking a public room to a private Group does not silently make it private.
- **Forms:** absolute local actions, literal query ampersands and one unrestricted final text field accommodate the original serializer. Attribute entities are not decoded; only spaces are escaped. New backend form fields are not claimed as recovered historical payloads.
- **Historical accuracy:** the binary establishes client behavior, not server billing, moderation policy, catalog products or missing HTML. Seed data, test credits, OTP, limits and replacement content remain explicit reconstruction choices.
